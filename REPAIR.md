# REPAIR: one fix per FAIL code

Run `bin/doctor.sh` (Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File bin/doctor.ps1`), find the code, apply the fix (ask the user before any change), then verify with the doctor. On Windows, a row in [Windows](#windows) replaces the macOS row with the same code; codes without a Windows row (sign-in, reply, sandbox, pairing, Local Bot, browser) are fixed the same way on both. If a code is missing here, or the fix doesn't work: stop and report the doctor output. This file grows from real cases, and every new real problem gets a code.

## Windows

Windows 11, Windows PowerShell 5.1. Every script runs as `powershell -NoProfile -ExecutionPolicy Bypass -File bin/<script>.ps1 …` (that one process only; forward slashes work in PowerShell and in Claude Code's Git Bash).

**Refresh PATH**: the AI app's shell keeps the PATH it started with, and every command the agent runs is a new process, so this line run on its own changes nothing. After each winget install, put it at the start of **the same command** that needs the new tool, e.g. `<line>; node -v` or `<line>; git clone …`. From Git Bash (Claude Code), put the line and the check inside **one** `powershell -NoProfile -Command "…"`. Fallback: the person restarts the Codex / Claude app. `bin/doctor.ps1` and `bin/install.ps1` run it themselves, so verify with the doctor:
`$env:Path = (($env:Path, [Environment]::GetEnvironmentVariable('Path', 'Machine'), [Environment]::GetEnvironmentVariable('Path', 'User')) -join ';' -split ';' | Where-Object { $_ } | Select-Object -Unique) -join ';'`

**WAIT** lines are not failures. Today a Local Bot on Windows waits for the Windows build of T3 Code TPLUS; the Bot runs on our server (Provider → Server). AJ-PIN-00, AJ-TENT-03 and AJ-LOCAL-00 show WAIT until then: record them in the report, don't repair them. Never `Set-ExecutionPolicy`, never disable Defender, SmartScreen, UAC or the firewall. A UAC window is always confirmed by the person, never by you.
